# Architecture

Android 0.1.4 retains the native Java host and bundled browser UI from 0.1.2. It does not depend on a remote website. Windows desktop work is deferred; the Python venv is unused by the APK.

| Area | Code | Responsibility |
| --- | --- | --- |
| Mobile interface | `web/app.js`, `styles.css`, `chatgpt-ui.js` | Editor, research, review, themes and settings |
| Contextual reading links | `web/information-links.js` | Offline bounded concept offsets, unchanged-text reader parts, relevant retrieved sources and public-URL guards |
| Domain | `web/core.js` | Versioned projects, counts, Writer DNA, draft observations, citations, revisions and contribution ranges |
| AI and research | `web/services.js` | Direct-account and optional server adapters, data-separated prompts, request consent, context guards, proposals and official scholarly APIs |
| Documents | `web/documents.js` | Bounded imports, export and print preview |
| Native adapter | `web/platform.js` | Cancellable promise bridge, storage and file operations; browser fallback |
| Durable draft input | `DraftInputStore.java` | Bounded synchronous private AtomicFile staging, corruption preservation and consumed-input tombstone |
| Android shell | `MainActivity.java` | Pinned-origin WebView, atomic private state/recovery, background requests and SAF |
| Accounts | `ChatGPTConnection.java`, `OAuthProtocol.java` | PKCE/loopback OAuth, signed identities, native encrypted tokens, accounts, refresh/revocation and terminal SSE handling |
| Browser callback transport | `LoopbackCallbackServer.java` | Concurrent bounded loopback peers, strict request/state validation, absolute deadlines and cancellation |
| Sign-in lifetime | `SignInKeepAliveService.java` | Temporary user-started foreground lifetime, readiness before the browser, and attempt-scoped completion/cancel/timeout cleanup |
| Remote writing contract | `AssistRequest.java`, `ChatGPTSessionState.java` | Exact reviewed instructions/input, bounded full payloads, eligible per-account models, quota and unusable-session handling |
| Updates | `AppUpdates.java`, `UpdateProvider.java` | GitHub releases, hash/package/version/certificate checks and Android install handoff |
| Build | `scripts/` | Local SDK, esbuild, javac/D8/AAPT2, ZIP alignment, release signing and verification |

The deployed phone cannot reach the user's PC. Primary AI calls go directly from Android to OpenAI over HTTPS using the encrypted account session. Each draft-assistance request needs a fresh preview/approval of an immutable payload; changed context invalidates approval. Native writing requests translate trusted application instructions to Responses instructions and put draft data in user input, omit unsupported parameters/tools, and require terminal stream completion. Neither a PC endpoint nor USB reverse is involved.

Browser authorization returns to an ephemeral `127.0.0.1` listener on the same phone. `LoopbackCallbackServer` processes up to 12 peers concurrently, bounds request lines to 8 KiB and headers to 16 KiB, and enforces an absolute five-second peer deadline within the overall sign-in deadline. An idle browser preconnection, malformed request or disconnected peer cannot terminate the whole attempt. Only the exact callback path, permitted loopback Host, matching state and a code or explicit error can complete it. Responses contain generic return guidance rather than callback values. The caller owns the master listener; completion, cancellation and expiry clean up peer sockets and workers.

The old idle-peer failure was reproduced, then a normal Chrome attempt exposed a separate Android cached-process freezer failure on the Moto. The repaired flow starts `SignInKeepAliveService` from the visible app and waits for actual foreground readiness before opening the browser. This non-exported `specialUse` service is scoped to one user-initiated sign-in, uses a generic temporary notification with return/cancel controls, and has a ten-minute backup cap. The sign-in worker closes its lease in `finally`; completion, cancellation, task removal, failure and timeout stop it. Old attempt cleanup cannot stop a newer attempt. It has no boot start or sticky restart and requires no global battery/freezer, browser or firewall changes. Real normal Chrome sign-in and subsequent service shutdown passed on the final 0.1.4 repair; see [verification](VERIFICATION.md). The listener and service remain entirely on the phone.

Full papers are not sent to scholarly APIs or the separate ChatGPT research action, which retain the minimal query/excerpt contract. Approved writing requests can include the full draft and assignment context. Optional advanced server support remains available for other environments. Offline editing and deterministic analysis do not need an AI account; no on-phone language model is bundled. Imported text and sources cannot run commands, invoke bridge methods or choose file paths. HTML is escaped; the WebView blocks external resources/navigation, direct web requests, frames and inline scripts.

Projects use versioned `.d2d` JSON and atomic app-private storage. This keeps drafts, research and revisions together without a remote database. Tokens and signing keys are separate from project storage and exports. Portable domain/service modules can support a later Windows interface.

The 0.1.4 additions retain those modules: durable pasted-draft entry, a separate contextual reading view, and permanent About dedication. Android staged text/cursor/scroll use synchronous `DraftInputStore` writes to app-private `draft-input.json`. `AtomicFile.finishWrite` commits before the UI reports success. The first load migrates a valid legacy WebView record once; thereafter native data is authoritative. A committed empty `null` tombstone prevents stale asynchronous browser data from resurrecting a consumed paste. A best-effort localStorage mirror supports browser compatibility, without serving as Android's durability guarantee. Corrupt native data is retained and cannot be silently overwritten by pause/autosave. Explicit project creation saves successfully before clearing staging; global Autosave does not control it. Leading blank lines are assigned as textarea values after rendering to avoid HTML parser newline removal. Dialog titles are escaped consistently. Information links recompute from current text, reject stale ranges, and never become document edits, exported paper text or formal citations automatically. Existing source/evidence review and explicit external opening remain the boundaries for live information.

Builds use the existing SDK pipeline rather than Gradle. Clean candidate builds replace generated web/native output only; previous signed APKs and source checkpoints remain intact. [VERIFICATION.md](VERIFICATION.md) separates executed current checks from historical results. A prior Samsung hosted-search request returned a usage-limit diagnostic. That inference request was not rerun for this sign-in repair, so the current Moto account's inference allowance and hosted web-search outcome remain unknown. Successful sign-in and model-catalog loading do not establish successful writing or browsing.
